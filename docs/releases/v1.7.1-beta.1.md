# Tool Atlas v1.7.1-beta.1

This beta includes the merged main-branch bug fixes and adds npm-only startup, optional local Docker Studio, optional Caddy settings, and health checks. The experimental Agent Catalog remains outside this release.

## Changes

- Approved PDF/PPTX guide downloads work with the correct MIME type and disposition.
- Malformed credential bodies return an authentication failure rather than an internal server error. API routes return JSON errors and accurate method responses.
- Catalog hierarchy handling and generated-text checks work with Windows paths and CRLF input.
- Software releases preserve their configured default/order, reconcile renamed or removed versions, serialize saves, and restore files on failed publication.
- Install with `npm ci`; `npm start`, `npm run dev`, and `npm run serve` build before serving. PowerShell users can use `npm.cmd`. The Windows launcher stops on a failed build.
- Caddy accepts empty or omitted `SITE_DOMAIN` and `ACME_EMAIL`. No domain selects HTTP; a public hostname selects automatic HTTPS, with optional ACME contact email.
- The static Docker image exposes `/api/health` as JSON. Container health checks use this endpoint; `docker compose ps` shows the status.
- The separate `compose.studio.yaml` builds a local Studio container on `127.0.0.1:8081`. Its current token is available through `docker compose -f compose.studio.yaml logs --tail=50 studio`; restart rotates it. Writable checkout mounts retain catalog/document edits.

## Artifacts and startup

- Source tag: `v1.7.1-beta.1`
- Static Linux/amd64 image: `ghcr.io/shalevz923/shalevsoftwaresite:1.7.1-beta.1`

```bash
docker pull ghcr.io/shalevz923/shalevsoftwaresite:1.7.1-beta.1
docker run --rm --read-only --tmpfs /tmp:rw,noexec,nosuid,size=16m -p 127.0.0.1:8080:8080 ghcr.io/shalevz923/shalevsoftwaresite:1.7.1-beta.1
```

Probe `http://127.0.0.1:8080/api/health`. The published image remains NGINX-only and has no Studio token. For Studio, check out this source tag and follow [Docker operation](../DOCKER_OPERATIONS.md). The tag workflow verifies source, then publishes the static image and provenance when supported; verify the completed run and record the immutable digest before deployment.

## Validation and beta limits

The combined fixes pass 137 automated tests, TypeScript, the production build, and artifact checks. CI verifies npm and pnpm on Linux and Windows. Container smoke checks cover HTTP health through Caddy, optional ACME email, preserved HTTPS policy, local Studio token logs, authenticated persistent saves, and token rotation.

Target-PC acceptance, external DNS/TLS, and the running work-PC server's health remain separate operational checks. A live server URL is needed to perform that health probe. Studio stays local to its Docker host; public Caddy does not route to its write APIs. Review Studio edits and rebuild before publishing them to the static site.
